# The upload folder

Everything in here is for the Meta Horizon Store submission form. What is ready, what is not, and
which claim each piece rests on.

Regenerate the rendered art with `python3 store/make-assets.py` — it draws from
`TMessagesProj_AppQuest/src/main/res/drawable/nicegram_mark.xml`, the vector the running app uses,
so the store art and the product cannot drift apart. The screenshots are captures and are not
regenerated by that script.

## Not ready, and neither is a coding problem

**The six screenshots that show the app in use.** Named in `../assets-checklist.md`: the quiet
chat list, an open conversation, dictation mid-recognition, the exceptions screen, the digest,
headset settings. Every one is behind sign-in. The capture route works — the onboarding frames
above came off the Spatial Simulator — so what is missing is one signed-in session with
conversations that look like conversations, not a tool.

Once signed in, the whole set takes minutes:

```sh
export ANDROID_SERIAL=emulator-5554          # or the headset's ip:5555
adb exec-out screencap -p > chat-list.png    # repeat per screen
```

On a real headset prefer Meta's camera service — the MCP tool `take_screenshot` with
`method='metacam'` — because `adb exec-out screencap` there returns the compositor frame rather
than the panel.

**Two things about the onboarding frames that are untested rather than known:**

- whether Meta accepts a **Spatial Simulator** capture where its rule says "captured in the
  headset". The simulator is Meta's own tool and renders the same panel; nothing here proves a
  reviewer treats the two alike.
- whether a near-square **0.935 aspect** suits placements that expect 16:9.

Treat them as a candidate set. If either answer is no, re-shoot on a Quest — the files are
replaceable without touching anything else.

**A trailer.** Optional at first submission, strong for the listing. Not attempted.

## Before uploading

Re-read Meta's current asset requirements. These sizes are the common shapes rather than a spec
read on the day — asset requirements change, and a stale spec is a rejection. The rules that do
not change are in `../assets-checklist.md`: transparent logo background, nothing in the cover's
top or bottom fifths, no other platform's hardware anywhere, a trailer under two minutes.
